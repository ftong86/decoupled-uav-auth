# Experiment Map

This table maps the experiments described in the paper to the source directories in this repository.

| Paper experiment | Source |
| --- | --- |
| Formal security verification (Section VI-C, Fig. 4) | `tamarin/` — normal authentication, message-loss recovery, dual-domain execution, post-session compromise and bounded state handoff |
| Protocol construction (Section V) | `protocol/src/protocol_core.cpp`, `crypto.cpp`, `root_provider.cpp`, `state_store.cpp`; function-level map in `protocol/docs/protocol_mapping.md` |
| Cryptographic primitive timing (Tables II–III) | `benchmarks/openssl-suite/`, `benchmarks/primitives/` |
| Mobility scenarios and comparative authentication (Sections VII-C, VII-D) | `simulation/ns3-uavma-module/model/`, `simulation/ns3-uavma-module/bi/`, `configs/scenarios/` |
| A3-event-to-authentication-completion measurement, CPU and message accounting | `simulation/ns3-uavma-module/model/uavma-ns3-transport.cc`, `uavma-measurement-ledger.h`, `uavma-p4-cpu-model.h` |
| Multi-UAV scalability and concurrent authentication | `scripts/e5/make_e5_scenes.py`, `make_e5_v2_scenes.py`, `make_e5_v2_p_only.py`; `scripts/run_one.sh`, `run_job.sh`, `run_batch.sh`; `simulation/e5/model/`, `simulation/e5/patches/` |

Concurrent-authentication scenes are not stored as separately named scenario files. They are produced at run time by the generic generators above with dynamic arguments (for example `--n 150 --layout fixed`) from the templates in `configs/scenarios/`, then dispatched by the batch drivers; the shared CPU-pool code is in `simulation/e5/model/`.
| State-machine mechanism prototype (Section V) | `protocol/prototype_validation/prototype_validation_v2.cpp` |
| Clock-independence ASR/FRR grid | `protocol/clock_independence/clock_experiment.cpp` |
| M2/M3 message-loss and state recovery | `protocol/state_recovery/`, `protocol/src/e3_main.cpp`, `protocol/tests/test_recovery.cpp` |
| Handler-cost calibration | `protocol/src/e1_main.cpp`, `protocol/scripts/run_e1.sh` |
| Standalone protocol tests | `protocol/tests/`, `protocol/scripts/run_s2.sh` |
| N=500 four-seed scalability runs | `scripts/e5/e5b_n500_formal4.py`, `e5b_n500_durable_autowaves.py`; E5 V2 overlay installer `scripts/e5/install_e5_v2.py` |

The code uses `P` for the proposed scheme, `A_JOINT` for the joint trigger policy, `A-Time` for the timestamp/window baseline and `A-Retry` for the recovery ablation. Clock-offset configurations and the loss-recovery matrix are generated by `protocol/src/e3_main.cpp`; single-UAV scene files are generated by `scripts/make_scenes.py` and multi-UAV scenes by `scripts/e5/`.

Build and execution commands are listed in `docs/ENVIRONMENT.md`; module-level notes are in the README files of each directory.
