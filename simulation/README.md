# ns-3 / IoD-Sim Simulation Sources

## `ns3-uavma-module/`

Custom ns-3 contrib module for the network experiments. Copy it to `<IoD-Sim>/ns3/contrib/uavma/` before configuring ns-3 (see `docs/ENVIRONMENT.md`).

| Subpath | Purpose |
| --- | --- |
| `CMakeLists.txt` | Builds `libuavma` against ns-3 core, LTE, mobility, applications, OpenSSL and SQLite |
| `core/src/`, `core/include/uavma/` | Copies of the standalone protocol core in `protocol/` |
| `model/uavma-ns3-transport.cc/.h` | ns-3 application implementing M0–M3 over sockets, A3-event-to-completion latency, CPU and message ledgers, and dual-domain isolation |
| `model/uavma-event-policy.h` | `GOnly` / `EOnly` / `GE` event classification and `P` / `A_JOINT` variant selection |
| `model/uavma-cell-partition.h` | Cell-to-edge mapping and handover decision |
| `model/uavma-measurement-ledger.h` | Separation of network-only, pure-handler and calibrated latency classes |
| `model/uavma-p4-cpu-model.h` | Handler-cost profile parsing and CPU queue model |
| `bi/core/`, `bi/model/` | Bi et al. comparison scheme mapped onto the same simulation: crypto primitives, protocol engine, wire codec, mapped-auth application and Bi-gated A3 handover |

`protocol/ns3/uavma/sync_ns3_module.sh` copies the module and the standalone protocol core into an existing IoD-Sim build tree and wires `${libuavma}` into the `scenario` target.

## `patches/`

* `0001-*.patch` … `0011-*.patch` — ns-3.45 interoperability patches for IoD-Sim 4.1.0 / 5G-LENA (geocentric mobility API, geographic positions, IRS spectrum channel, LTE quirks, parabolic antenna elevation).
* `uavma-ns3-transport.cc.patch`, `uavma-ns3-transport.h.patch` — project patches for the custom transport.

Apply the numbered patches with `git am` to an ns-3.45 tree as described in `docs/ENVIRONMENT.md`.

## Running

```bash
cd <IoD-Sim>/ns3
./ns3 configure -d debug --enable-modules=iodsim,nr,point-to-point-layout,uavma
./ns3 build -j4
./ns3 run "scenario --config=<path-to-configs/scenarios/*.json> --RngSeed=33 --RngRun=3"
```

The transport supports overlapping authentication sessions. Multi-UAV scenes are generated by `scripts/e5/`, and the corresponding ns-3 module overlay is in `e5/`. Simulation outputs are written locally and are excluded from Git.
